# 后端代码问题修复计划

## 1. 问题分析

根据VSCode诊断信息，后端代码中存在以下主要问题：

| 问题类型    | 数量 | 主要影响文件                                                                                           |
| ------- | -- | ------------------------------------------------------------------------------------------------ |
| 已弃用API  | 4  | URIUtil.java, CrawlStrategyResolverImpl.java, ThreadPerformanceController.java, JsoupEngine.java |
| 未使用导入   | 3  | SasacGovDataParserImpl.java, AsyncConfig.java                                                    |
| 未使用字段   | 2  | CrawlAggregationFacadeImpl.java, JsoupEngine.java                                                |
| 未使用方法   | 5  | JsoupEngine.java(2), SasacGovDataParserImpl.java, GzwShGovDataParserImpl.java                    |

## 2. 修复计划

### 2.1 修复已弃用API

1. **URIUtil.java**：将已弃用的URL构造函数替换为URI类

   * 使用`URI.create()`和`URI.resolve()`方法替代URL构造函数

2. **CrawlStrategyResolverImpl.java**：将已弃用的URL构造函数替换为URI类

   * 使用`URI.create()`方法替代URL构造函数

3. **ThreadPerformanceController.java**：移除对已弃用的Thread.getId()方法的使用

   * 考虑使用其他唯一标识符

4. **JsoupEngine.java**：移除已弃用的sslSocketFactory方法调用

   * 简化SSL配置

### 2.2 移除未使用的导入、字段和方法

1. **SasacGovDataParserImpl.java**：移除未使用的导入和方法

   * 移除`java.net.MalformedURLException`和`java.net.URL`导入

   * 移除未使用的`formatter`变量

   * 移除未使用的`parseDateTimeWithFallback`方法

2. **AsyncConfig.java**：移除未使用的`java.util.concurrent.Executor`导入

3. **CrawlAggregationFacadeImpl.java**：移除未使用的`status`字段

4. **JsoupEngine.java**：移除未使用的字段和方法

   * 移除未使用的`environment`字段

   * 移除未使用的`mergePageData`和`randomDelay`方法

5. **GzwShGovDataParserImpl.java**：移除未使用的`parseDateTimeWithTime`方法

### 2.3 提取重复的字符串常量

1. **WebSocketHandler.java**：将重复的`/topic/tasks/`字符串提取为常量

2. **BaseInterceptor.java**：将重复的`unknown`字符串提取为常量

### 2.4 其他优化

1. **GzwShGovDataParserImpl.java**：优化异常处理，使用未命名模式替代未使用的异常变量

2. **JsoupEngine.java**：处理TODO注释，优化条件结构

3. **JsoupEngine.java**：简化空方法，添加注释说明

## 3. 修复顺序

1. 修复已弃用API（优先级最高）
2. 移除未使用的导入、字段和方法
3. 提取重复的字符串常量
4. 其他优化

## 4. 预期效果

* 消除VSCode中的所有警告和错误

* 提高代码质量和可维护性

* 减少代码冗余

* 确保使用最新的API

## 5. 注意事项

* 修复过程中保持代码逻辑不变

* 确保修复后代码能够正常编译和运行

* 遵循项目现有的代码风格和规范

* 对于认知复杂度较高的方法，暂时保持不变，后续再进行重构
