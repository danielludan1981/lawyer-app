# 前端法律爬虫查询功能

## 目标

1. 基于pure-admin框架的风格，在已有frontend/admin模块的基础上，创建一个法律爬虫查询功能的模块

## 导航菜单

1. 首页之后添加一个网页爬虫一级菜单，包含**法规文章查询**二级菜单，点击后右侧内容区展示法规文章查询页面

## 法规文章查询页面设计

1. 布局上下分区域，上区域为查询表单，下区域为查询结果列表
2. 查询表单包含以下元素
    - 下拉输入框：用于选择查询时间范围
        - label：最近多少天
        - 输入组件：下拉选择框，可选值为1天、7天、15天、30天、60天、90天、180天、365天，对应的值为1、7、15、30、60、90、180、365
        - 默认值：30天
        - 约束：必填
    - 查询按钮：用于触发查询操作
3. 查询结果列表包含以下元素
    - 表格标题：以返回的任务名称为标题，例如“国务院官网-政策解读”
    - 表格：展示该任务抓取的法律文章，包括文章标题、发布日期、文章链接
        - 列：文章标题、发布日期、文章链接
        - 行：每个法规文章对应一行

## 交互设计

1. 用户点击查询按钮后，前端将发送查询请求到后端。由于爬虫任务可能需要一定时间才能完成，因此前端需要轮询查询任务状态，直到任务状态为成功或失败再展示查询结果列表
2. 当轮询查询任务状态时，前端需要展示一个加载中提示，例如“加载中...”
3. 任务创建成功后，后端将返回任务ID给前端，前端每隔5秒轮询一次任务状态
4. 任务状态为成功后，前端将获取任务结果，展示在查询结果列表中
5. 任务状态为失败后，前端需要展示一个错误提示，例如“查询失败，请稍后重试”

## 查询过程API设计

1. 服务端的baseUrl为 <http://localhost:8082/api/crawler>
2. 创建聚合爬虫任务, 触发爬虫任务，返回任务ID（data字段）
    请求示范如下：

    ``` bash
    POST {{baseUrl}}/custom/aggregationTasks/govArticles
    Content-Type: application/json

    {
        "publishedInDays": 10
    }
    ```

    响应示范如下

    ``` json
    {
        "code": null,
        "data": "59c2eab4-ee5a-4273-849a-d6daafa016bf",
        "error": null,
        "pagination": null,
        "success": true,
        "timestamp": "2026-01-18T12:37:54.2470538"
    }
    ```

3. 查询任务状态, 根据任务ID查询任务状态和结果（data字段）
    - data字段主要包含以下元素
        - status: 任务状态。 可选值为CREATED（创建未运行）, RUNNING（运行中）, SUCCESS（成功）, FAILED（失败）, CANCELLED（取消）
        - crawlResults: 爬虫任务执行结果，为数组，对应如何渲染页面查询结果的每个表格标题和表格数据的逻辑如下
            - 表格标题：使用metadata.taskName字段值
            - 表格数据：使用pageResultMap中的数据（内部data对象），每个键值对对应表格的一行数据，键为文章链接，值为文章标题、发布日期、文章链接

    请求示范如下：

    ``` bash
    GET {{baseUrl}}/aggregationTasks/330d8501-7007-4eb9-9a9c-44ed9caf65ab
    ```
