# 后端爬虫增强Parser选择策略

## 目标

1. 增强Parser选择策略DataParserStrategyImpl找到了多个DataParser实现类时，不直接抛出异常，而是进一步通过匹配度结果测试符合要求的DataParser的匹配度，如果匹配度不同，则选择匹配度最高的DataParser实现类，否则当匹配度一样时才抛出异常

## 代码

### **SelectorMetadataKey** 常量类
新增以下常量
- USER_DATA_PARSER：数据解析器元数据键，用于指定解析器名称以提供给DataParserStrategy选择合适的解析器。

### **DataParser**接口
增加以下方法
```java
/**
 * 获取匹配度
 * @param metadata 元数据
 * @param data 数据
 * @return 匹配度, 值越高证明约匹配
 */
public int getMatchScore(Map<String, Object> metadata, Object data)
```

### **AbstractDataParser**抽象类
实现getMatchScore方法
- 根据传入的metadata传入的url key，如有协议头去除协议头(http或https)，返回与getUrlPrefix()返回的前缀撇配的字符数

###  **DataParserStrategyImpl**策略类
增强selector方法, 选择优先顺序由高到低如下
- 先判断是否有指定数据解析器名称（通过从metadata中获取USER_DATA_PARSER键对应的值），有则仅根据名称选择解析器
    - 名称匹配则作为候选解析器，加入到候选解析器列表中
- 如没有指定数据解析器名称，则根据解析器的support方法返回值筛选出符合条件的解析器
    - 返回true则作为候选解析器，加入到候选解析器列表中
- 根据候选解析器列表，判断该如何返回
    - 如果候选解析器列表为空，则抛出异常，提示用户检查解析器配置
    - 如果候选解析器列表只有一个解析器，则直接返回该解析器
    - 如果候选解析器列表有多个解析器，则判断每个Parser返回的getMatchScore值，候选列表仅保留匹配度最高的解析器
        - 如果候选解析器列表只有一个解析器，则直接返回该解析器
        - 如果候选解析器列表为空，则抛出异常，提示用户检查解析器配置

###  **NoopDataParserImpl** 无操作解析器实现类
- 实现getMatchScore方法，返回0
- 实现support方法，当metadata中没有指定dataParser名称为"noop"时，返回true，否则返回false
- getName方法，返回"noop"
- parse方法，直接返回传入的数据，不做任何处理
