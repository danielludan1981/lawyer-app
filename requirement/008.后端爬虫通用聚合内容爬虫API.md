# 后端通用聚合内容爬虫API

## 目标
1. 提供通用的数据请求聚合DTO，能够包含不同来源的爬取请求
2. 提供通用的数据响应聚合DTO，能够包含不同来源的爬取数据
3. 支持并行执行多个爬取任务，并能监控和查询父子（原爬虫任务为子任务，聚合任务为父任务，父任务ID仅用于关联实际的爬虫子任务ID并提供整体状态任务查询结果）任务的执行状态和结果

## 数据结构
1. 通用数据请求聚合DTO（CrawlAggregationRequestDTO）
   - 包含多个数据请求DTO（CrawlRequestDTO）的列表，每个DTO代表一个具体的爬取请求
2. 通用数据响应聚合DTO（DataResponseAggregateDTO）
   - 包含多个数据请求DTO（CrawlResponseDTO）的列表，每个DTO代表一个具体的爬取请求
   - TaskMetadata metadata: 复用现有的元数据结构，但当前实际赋值以下几个字段（将来可以扩展）
     - taskId: 聚合任务ID, 父任务ID
     - taskName: 目前固定为“聚合爬虫任务”
     - createdAt: 聚合任务创建时间戳
     - createdByUserName: 聚合任务创建者，目前和子任务保持一致
   - TaskStatus status: 复用现有的子任务状态，每个状态的解释如下
     - CREATED: 聚合任务已创建，等待执行
     - RUNNING: 聚合任务正在运行中，至少有一个子任务正在运行中
     - SUCCESS: 聚合任务所有子任务都成功完成
     - FAILED: 聚合任务至少有一个子任务失败
     - CANCELLED: 聚合任务被用户取消

## API接口
扩展CrawlController, 风格保持一致
1. 创建聚合任务（POST /aggregationTasks）
   - 请求体：CrawlAggregationRequestDTO
   - 响应体：DataResponseAggregateDTO
2. 查询聚合任务状态（GET /aggregationTasks/{aggregationTaskId}）
   - aggregationTaskId - 聚合任务ID
   - 响应体：DataResponseAggregateDTO
3. 取消聚合任务（取消所有关联子任务）（DELETE /aggregationTasks/{aggregationTaskId}）
   - aggregationTaskId - 聚合任务ID
   - 响应体：成功取消消息

## 限制
1. 在现有的基础上进行扩展，不改变原有爬虫的功能和接口。
